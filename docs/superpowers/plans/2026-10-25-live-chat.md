# Live Chat for Every Visitor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pulsing floating chat button for every visitor; the first message (with an email) opens their account and the chat in one step; afterwards the button opens straight to the conversation.

**Architecture:** One server step (`startChat`) opens the account on this device (the existing `openAccount`) and sends the first message as the customer (the existing `sendMessage`), so the conversation, its inbox entry and the team's unread count are exactly what the order chat already uses. The launcher always renders the button; its window shows a start form until the device has a conversation, then the existing `ChatPanel`.

**Tech Stack:** Next.js 16.4, React 19, Prisma 7, zod 4, zustand, radix-ui Dialog (non-modal on computers), Tailwind v4, Phosphor icons, Pusher (existing). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-25-live-chat-design.md` (mockup `.superpowers/brainstorm/80313-1792879793/content/live-chat.html`)

## Global Constraints

- No commits unless the owner asks; a ledger line per task.
- Copy (spec): header "Best Vape Shop" / "We usually reply in a few minutes"; "Start the conversation"; "Hi! Questions about a flavour, an order or delivery? Send us a message and a real person will reply."; "Your email, so we can reply"; "Type a message…"; "Sending opens your account with this email. Adults 18+ only."; "Chatting as <email>"; unavailable: "Start a new chat from the chat button."
- Limits: `accountLimiter` (15/IP, 10/email per 15 min); honeypot field `website`; message 1–4000 characters (the chat's own rules).
- Privacy: a typed email on a new device gets its own new chat (account rule); no other device's messages.

## Review Focus

1. **A visitor whose device already has a chat submits the form in a stale tab.** Expected: the message goes to the device's own chat; no second account switch. Test: Task 1 `a signed-in device keeps its own chat`.
2. **Bots filling the form.** Expected: the honeypot or the limit stops them without creating chats. Test: Task 2 e2e `the trap field stops bots`.
3. **The button over other bottom things on phones** (install card, sticky buy bar). Expected: never overlapping. Test: Task 3 e2e `on a phone the button clears the install card`.
4. **The window open while a pop-up is due.** Expected: the pop-up waits (it already waits for open dialogs). Test: Task 3 e2e `no pop-up over the open chat`.
5. **The order chat after the change.** Expected: the order page still opens the chat with the invoice. Test: Task 3 e2e `ordering still opens the chat with the invoice`.
